# spec: 工具系统（tool use）

状态：已完成（2026-06-04）。实现见 `coreagent/tools/`、`coreagent/agent.py`、`coreagent/prompts.py`，
provider / conversation / tui / main 已扩展接入；验收见 checklist.md（离线 56 passed + 真实模型四路径 e2e）。

> 注：本 spec 的「单轮工具调用」约束已被 #0004（Agent 循环）supersede——升级为多轮 Agent Loop；其余能力（Tool 接口 / 六工具 / 确认 / provider 工具解析 / tool_use·tool_result 格式）仍有效。

## 背景

#0001 / #0002 交付了工程化的纯对话 TUI。本 spec 给 CoreAgent 装上工具系统：模型不再只能输出文本，而能通过工具读 / 写 / 改文件、执行命令、按模式找文件、搜索代码内容。一个回合的流程是——模型在回复里发起工具调用 → 本地代码执行 → 结构化结果回灌对话历史 → 模型据结果再回复一次。

本 spec 只做**单轮工具调用**：一个用户输入内，模型最多发起一轮工具调用、据结果作答即停。多工具连环调用 / 自动循环（Agent Loop）留到后续 spec。

本步明确不做：

- 不实现 OpenAI 协议的工具调用；OpenAI 维持纯对话（#0001 行为不变），工具能力只接 Anthropic provider。
- 不做 Agent Loop（多轮自动连环调用）。
- 不打包非 linux-x64 平台的 ripgrep 二进制——按平台解析的骨架就位，其余平台二进制留到打包发布时补。

## 与 #0001 / #0002 的关系

- **向后兼容地扩展 provider 契约**（#0002 刻意保住的基础上）：流式接口新增「工具清单」入参；完成事件新增承载「已组装的工具调用」。THINKING / TEXT / DONE 三类型与纯对话路径行为不变——**不传工具时产出与此前完全一致**。
- **扩展会话消息**：Conversation 支持 assistant 的 tool_use 块与后续 user 的 tool_result 块（Anthropic 多轮工具格式）；纯对话消息格式不变。
- OpenAI provider、TUI 视觉与命令集、四个配置字段语义均不变。

## 目标用户

在终端用 CoreAgent 的开发者——希望助手能真正读改文件、跑命令、查代码，而不只是聊天。

## 能力清单

工具与执行：

1. 统一的 **Tool 接口**：每个工具声明名称、描述、参数 Schema，并实现执行方法；工具自带「是否需执行前确认」的标记。
2. 六个核心工具：**读文件、写文件、改文件、执行命令、按模式找文件（glob）、搜代码内容（grep）**。
3. **改文件走原文唯一匹配替换**：给定原文片段在目标文件中须唯一；匹配不到或匹配多处都返回清楚的错误，让模型据此重试。
4. **执行命令带超时**：超时与执行失败都包成结构化结果返回，不让进程挂死、不抛裸异常。
5. **glob** 用标准库遍历 + gitignore 过滤（经 pathspec，不手写忽略规则），默认排除被 gitignore 命中与 .git 的路径。
6. **grep** 调用随包分发的 ripgrep 二进制，固定以「参数列表 + shell=False」调用，参数由本地代码拼装、模型不构造命令字符串；不提供 Python 回退。本步只落地并验证 linux-x64 一份二进制，并打通「按平台解析二进制路径」的骨架。

注册与调度：

7. **工具注册中心**：集中登记工具、按名查找、转成 API 认得的工具清单。
8. **统一执行入口**：按名分派执行，对超时与任意异常做结构化错误包装后返回给模型——失败即结构化结果，而非崩溃。

模型对接：

9. provider 把工具清单传给 Anthropic API，并**解析流式工具调用**：拼接流式返回的参数 JSON 碎片，得到完整工具调用。
10. 工具结果**回灌对话历史**后，模型据此**再回复一次**自然语言答复即停；该轮答复若再请求工具，本步忽略、不继续执行（不循环）。一个用户输入内最多两次模型调用。
11. 给 Agent 一段**精简系统提示词**：说明身份（终端编程助手）、可用工具、以及「需读 / 改文件时调用工具而非臆测」的规范。

安全：

12. **改写类与命令工具（写文件 / 改文件 / 执行命令）执行前需用户在 TUI 确认**；读取类（读文件 / glob / grep）直接执行。用户拒绝时把「已拒绝」作为结构化结果回灌，模型据此调整。无硬性目录沙箱。

## 非功能要求

- 纯对话路径（不传工具时）产出与 #0001 / #0002 完全一致；流式首字节延迟不变。
- 工具失败一律转结构化结果回灌模型，进程不崩、不向用户抛裸栈。
- 测试不依赖真实网络与 API key（provider 用假事件流、工具用临时目录验证）。
- ripgrep 调用恒为「二进制 + 参数列表 + shell=False」；模型输入不参与命令字符串拼接。

## 设计骨架

```
coreagent/
├── tools/
│   ├── base.py        Tool 抽象 + 结构化结果类型 + 需确认标记
│   ├── registry.py    注册中心：登记 / 按名查找 / 转 API 工具清单 / 按名执行（超时 + 错误包装）
│   ├── read / write / edit / run_command / glob / grep  六个工具各一文件
│   └── ripgrep.py     按平台解析 ripgrep 二进制路径（本步仅 linux-x64 就位）
├── bin/               随包分发的 ripgrep 二进制（本步 linux-x64）
├── prompts.py         Agent 系统提示词
├── agent.py           单轮工具编排：流式(带工具) → 确认 → 执行 → 回灌 → 再流式一次 → 停
├── providers/
│   ├── base.py        stream_chat 增工具入参；完成事件承载工具调用
│   └── anthropic.py   传 tools；解析流式工具调用（碎片拼接）
├── conversation.py    tool_use / tool_result 消息块支持
├── tui.py             确认 UI + 工具调用 / 结果渲染 + 接 agent 编排
└── main.py            组装：注入注册中心与系统提示词
```

依赖与结构决策：

- glob 的 gitignore 交给 **pathspec**（声明式、语义正确），遍历与文件名匹配用标准库，不为此另引依赖。
- grep 用 **bundle 的 ripgrep**：速度、gitignore 语义现成，跨机行为恒定；固定参数列表调用规避注入。不引 Python 检索实现作回退——全平台都 bundle，就没有「缺失」一说。
- 工具编排独立成 `agent.py`，与 TUI 渲染 / 确认经回调解耦（沿用 #0002 `on_retry` 的解耦风格），为后续 Agent Loop 留缝。

## Out of Scope

- OpenAI 协议的工具调用（本步仅 Anthropic）。
- Agent Loop / 多工具连环自动调用（下一 spec）。
- 非 linux-x64 平台的 ripgrep 二进制打包（仅留解析骨架）。
- 目录沙箱 / 命令白名单 / 权限分级（本步仅「改写与命令需确认」）。
- RAG / LangGraph / MCP / FastAPI。
- 工具调用参数的逐字流式渲染（仅以紧凑形式展示工具名 / 结果）。
