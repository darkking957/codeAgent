# 0006 提示词模块化装配 + 缓存通道分离 + 动态注入

把全局指令从「单条字符串」重构为「按职责分模块的有序装配」，并把稳定内容与变化内容分到
不同的请求通道，使 Anthropic prompt caching 在多轮 agent loop 里真正生效；同时引入一种
运行中注入补充指令的临时消息形式（不污染缓存、不落历史），首个消费者是 plan 模式提醒。

## 背景

当前（见 `coreagent/prompts.py`、`coreagent/providers/anthropic.py`、`coreagent/agent.py`）：

- 系统提示词是单条字符串 `SYSTEM_PROMPT_BASE` + 拼工具名，**无分模块、无环境信息、无缓存**。
- Anthropic 请求里 `system` 是纯字符串、`tools` 直传，全程**无 cache_control 断点**；
  响应里也**未解析** `cache_read_input_tokens / cache_creation_input_tokens`。
- agent loop **每轮都把整条 history 重发**（`conversation.get_messages()`），无缓存时
  每轮重算整条上下文，多轮场景代价最大。
- `plan_only` 目前只是**静默拦截写类**→记 `plan_items`，**完全没给模型注入任何 plan 提示**，
  模型并不知道自己在 plan 模式。
- e2e 环境走 DeepSeek 的 Anthropic 端点，**不保证**支持 cache_control、也不保证回传缓存字段。

## 目标用户

CoreAgent 自身的「提示词 / 请求装配」层。直接受益者是后续要往全局指令里插新模块、依赖缓存
降本、或新增模式注入的开发（即我们自己）。终端用户无感知（行为应保持一致，只更省更可控）。

## 能力清单

1. 全局指令拆成 7 个命名职责模块（身份 / 行为 / 工具使用 / 代码规范 / 安全边界 / 任务模式 /
   输出风格），按固定优先级在一个有序列表里拼接；新增模块 = 加一个常量 + 注册进有序列表（轻量分节，**不引入** PromptModule 注册表抽象）。
2. 稳定内容（系统模块 + 工具清单）走可缓存通道：在 Anthropic 请求的稳定前缀打 cache_control 断点。
3. 多轮场景：每次请求在「最后一条已定型消息」打**滚动** cache_control 断点，让不断增长的
   transcript 跨轮命中缓存；断点总数受控在 Anthropic 上限内。
4. 环境信息（工作目录 / 操作系统 / 日期 / git 分支 + 简短状态）**会话启动时快照一次**、整会话不变，
   作为 `system` 尾部块放在稳定前缀断点**之后**（不进可缓存前缀，不写入持久化历史）。
5. 运行中可注入补充指令：一种**带特殊标签的临时消息**，放在滚动断点之后的 `messages` 尾部，
   不污染缓存、不落历史、不被模型当作用户输入去回复；本期落地「模式提醒」一种消费者，
   「外部工具上线 / 温和提示」留**前向钩子**（占位，不接 MCP）。
6. plan 模式提醒：注入提示告知模型处于 plan 模式、**继续提议写操作**（会被记录为计划、不执行），
   保留现有 `plan_items` 拦截语义不变；注入节奏 = **首轮全量 + 其余轮次精简**（两档）。
7. 关键规则在工具描述与全局指令里**双重强化**，覆盖模型默认偏好。
8. 缓存可观测：解析 Anthropic 响应里的缓存命中 / 创建字段，有则记录（可断言）、无则跳过并记日志；
   断点落位由单测验证，**不**以「真实命中」为硬性验收门槛。

## 非功能要求

- 不破坏 #0004 既有不变量：tool_result 顺序分离（历史按调用序、UI 按完成序）、取消三态补占位、
  `plan_only` 下 `plan_items` 产出语义。
- 不破坏 #0005：confirm 契约仍为 bool。
- OpenAI 路径行为不变：仍以单条 `system` 字符串发送、忽略 tools、不做缓存。
- 环境快照零每轮开销：会话内只采集一次（git 子进程只调一次）。
- 缓存断点数 ≤ Anthropic 上限（≤4）。
- provider 契约可向后兼容：扩展 `system` 以支持结构化块时，旧的「纯字符串 system」调用仍可用。

## 设计骨架

模块级（不锁函数名 / 参数 / 默认值，具体值见 checklist）：

- **提示词模块层**：把单条 base 拆成 7 个命名职责常量 + 一个按优先级拼接的有序装配，输出「稳定系统文本」。
  双重强化规则写进对应模块（工具使用 / 代码规范），同一规则也出现在相关工具的 description 里。
- **环境快照**：启动时采集 cwd / OS / 日期 / git 分支 + 简短状态，缓存为只读快照，格式化为带标签的环境块。
- **动态注入供给**：一个入口按当前状态（`plan_only` + 轮序）产出带特殊标签的临时块；plan 提醒文案
  传达「plan 模式 / 继续提议 / 会被记录不执行」；节奏首轮全量、其余精简；含「外部工具」前向钩子占位。
- **请求装配（Anthropic 边界）**：
  - `system` = [稳定模块块（打 cache_control）] + [环境快照块（不打）]；
  - `tools` 末尾按需打 cache_control（与稳定前缀同属可缓存区，位于 system 之前）；
  - `messages` 末尾的「最后一条已定型消息」打滚动 cache_control；
  - 动态提醒作为临时标签消息追加在滚动断点**之后**（每请求重建，不写入 `conversation`）。
- **缓存观测**：从流式最终消息的 usage 读取缓存创建 / 命中字段，记录日志并按需透出。
- **接入**：`main` 用新装配构建稳定 system；agent loop 把（轮序 / plan_only / 环境快照 / 动态提醒）
  经装配层注入到断点之后；env 与 reminder 均不写入 `conversation`（保持历史 append-only 可重放）。

两条推导设计（缓存前缀拼接顺序为 tools → system → messages 所致，请评审重点确认）：

- 环境块放在稳定前缀断点**之后**、而非「会话首条」——否则 session-specific 的 env 进入可缓存前缀，
  会破坏跨会话缓存命中。
- 动态提醒放在滚动断点**之后**的 messages 尾部——若放 system（位于滚动断点之前），其每轮变化会让
  滚动缓存永不命中。

## Out of Scope

- MCP / 外部工具真实接入（仅留前向钩子占位）。
- OpenAI 路径的缓存（行为不变）。
- 完整 PromptModule 注册表 / 适用判定 / 动态插入抽象（用轻量分节替代）。
- 每轮刷新 git 状态（用会话启动快照）。
- idea6 的「间隔 N 轮全量」第三档节奏（简化为两档）。
- 把「真实缓存命中（cache_read>0）」作为硬性验收门槛（端点不保证支持）。
