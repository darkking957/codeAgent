# #0005 富交互执行确认（确认 UI）

## 背景

写类工具（命令 / 写文件 / 编辑）执行前的确认，现状是一行 `[y/N]` 纯文本问句（复用主输入框、返回二态）。
信息量太薄：用户在按下 y 之前看不清「到底要执行什么」，也无法表达「这个工具本会话别再问我了」。

本期把这个确认环节升级成一个**内联富交互菜单**，复刻 Claude Code CLI 的确认风格，含六个视觉组件，并把
「同意 / 同意且本会话不再询问此工具 / 拒绝」三个出口落到方向键可选的菜单上。

延续 #0003（工具系统、执行前确认）与 #0004（多轮 Agent 循环）。**不改 #0004 的确认回调契约**：
循环侧仍只接收「同意 / 拒绝」二态，三态语义在 TUI 内收敛。故本期是新增能力，不 supersede 任何旧 spec。

## 目标用户

在终端里用本助手写代码的人——希望在放行一次有副作用的操作前，**一眼看清操作内容**，并能用方向键快速决策、
对信任的工具一次性免确认。

## 能力清单

1. 写类工具执行前，弹出**内联富交互确认菜单**取代 `[y/N]`，含六个组件：区域标签、内容预览块、分隔线、确认问句、选项列表、快捷键提示条。
2. **区域标签**：按工具类型显示一个 pill 小标签（强调色底 + 深色字），标明当前操作是「命令 / 写文件 / 编辑」哪一类。
3. **内容预览块**：等宽框内展示将执行的操作内容，并做语法着色——命令做 shell 高亮；编辑类显示原文→新文的彩色增删 diff（删行红、增行绿）；写文件按扩展名高亮内容首段。框下一行次要色文字给一句话描述。超长内容截断并提示余量。
4. **选项列表**：三项——同意执行 / 同意且本会话内不再询问此工具 / 拒绝。方向键 ↑↓ 导航（回绕）、数字键直选、回车确认、esc 或 Ctrl+C 取消（等价拒绝）。当前项高亮 + 左侧指示符，未选中项显示序号。
5. **本会话信任**：选「不再询问此工具」后，按**工具名**记住，仅本会话内存、**不落盘**；之后该工具的写操作直接放行、不再弹菜单。
6. **确认问句**：一句话问句，末尾光标周期性闪烁，表示正在等待输入。
7. **快捷键提示条**：底部低对比度小字，展示 ↑↓ / ↵ / esc，键名用细边框包裹。
8. **非交互降级**：检测到非 TTY（管道 / 重定向 / CI）时，自动回落为纯文本 y/N 确认（默认拒绝），不渲染富 UI、不记忆。

## 非功能要求

- **不改 #0004 确认回调契约**：确认环节对 Agent 循环仍只回传「同意 / 拒绝」二态；「本会话不再询问」纯属 TUI 内部状态，命中即直接回传「同意」。循环不感知第三态。
- **内联留痕**：富菜单在流式输出正下方就地渲染，不接管整屏、不清屏；确认后该帧保留在滚动历史里。
- **取消语义不变**：取消即拒绝；流式期间 Ctrl+C 仍能让循环优雅收尾（补齐 tool_result、配平历史），与 #0004 现状一致。
- **不引新三方依赖**：复用现有 prompt_toolkit（非全屏内联模式做方向键菜单与闪烁刷新）+ rich（语法高亮 / diff 着色）。
- **进程不因渲染崩溃**：预览构建对缺字段 / 异常输入要有兜底，渲染失败不拖垮确认（最坏回落为朴素文本）。

## 设计骨架

```
写类工具执行前
        │ 确认环节（TUI）
        ▼
   非 TTY ? ──是──▶ 纯文本 y/N（默认拒绝，不记忆）──▶ 同意 / 拒绝
        │否
        ▼
   工具名已在「本会话信任集」? ──是──▶ 直接同意（不弹菜单）
        │否
        ▼
   内联富菜单：六组件渲染 + 方向键/数字/回车/esc + 光标闪烁
        │ 三态决策
        ├─ 同意           ─────────────▶ 同意
        ├─ 同意且不再询问  ─加入信任集──▶ 同意
        └─ 拒绝 / esc / Ctrl+C ────────▶ 拒绝
```

- **内联菜单组件单独成模块**：预览构建、六组件渲染、闪烁态都做成纯函数（输入 = 工具调用 + 选中项 + 光标态，输出 = 可渲染内容），便于脱离 TUI 单测；交互应用（按键 → 决策）薄薄一层包在外面。
- **预览 / 高亮**借 rich 的语法高亮与 diff 着色能力；标签 / 选项 / 提示条的配色并入现有 TUI 主题色板。
- **TUI 侧**：维护「本会话已放行工具集」，把三态决策收敛成二态回传循环；降级分支在 TUI 入口处判定。

## Out of Scope

- **不改 Agent 循环的确认回调契约**（仍二态）→ 不 supersede #0004。
- **不重做** plan-only 的「计划列表审批」与 `/plan` 退出确认（沿用现状的 y/N）。新菜单组件未来可被它们复用，本期不动，避免越界。
- **不做跨会话持久化的永久信任**（不落盘、不写配置）。
- **不做按「工具名 + 参数」或按目录的细粒度信任**——仅按工具名。
- **不新增工具类型、不改任何工具的执行语义**；读类工具仍免确认、不受影响。
- **不引入「拒绝并附说明」第四出口**（本期三选；如需回灌自定义反馈，另开新号）。
