# spec: Agent 循环（Agent Loop）

状态：草稿

supersedes #0003 的「单轮」约束（一个用户输入最多两次模型调用、第二轮工具调用忽略）。#0003 其余能力——Tool 接口、六个核心工具、执行前确认、provider 流式工具解析、tool_use/tool_result 会话格式——继续有效，本 spec 在其上加循环。

## 背景

#0003 交付了**单轮**工具编排：一个用户输入内模型最多发起一轮工具调用、据结果作答即停，第二轮即便再出工具调用也忽略不执行。本 spec 把它升级为**多轮 Agent Loop**——模型可连环调用工具（读→改→验证）直到任务自然完成或触发边界，中途无需用户逐步推动。

设计原则对齐 Claude Code 的「最小脚手架，最大运行环境」：循环本体保持极简 while-loop（调模型 → 解析 → 执行工具 → 结果回灌 → 下一轮，无工具调用自然终止），不引入显式规划器 / 状态图 / LangGraph，让模型在丰富的工具运行环境里自由推理。状态以**追加方式**维护、保持可审计；权限钩子位 deny-first 但本 spec 只留位不实现规则。

## 与 #0001 / #0002 / #0003 的关系

- **原地把单轮 `run_agent_turn` 改造成多轮循环**：单轮是「轮数上限 = 1」的特例。函数签名与回调（confirm / on_tool / on_retry）形态保持，调用方（TUI）平滑接入。
- **向后兼容地扩展事件流**：单向推送流（thinking / text / done）三类型与纯对话路径行为不变；新增的循环级信号只在多轮场景产生可见效果，**不传工具、单轮自然结束时产出与 #0003 完全一致**。
- **扩展会话**：仍用 #0003 的 tool_use / tool_result 块；循环只是把「回灌→再调模型」重复多次。纯对话与单轮消息格式不变。
- OpenAI provider 仍维持纯对话（#0003 行为不变）；循环对其退化为单次调用。

## 目标用户

在终端用 CoreAgent 的开发者——希望助手能自己读文件→改代码→跑命令验证、多步连环把任务做完，而不是每一步都要人再敲一句话推一把；同时在高风险动作前能切到「只规划不执行」先看计划。

## 能力清单

循环本体：

1. **多轮 while-loop**：每轮依次「调模型（带工具）→ 解析响应 → 执行工具 → 结果回灌历史 → 进入下一轮」；某轮模型不再请求工具即自然退出。
2. **四个终止条件**，每轮开始前检查，任一满足即退出：模型本轮无工具调用（自然完成）、达到轮数上限、收到取消信号、发生不可恢复错误。
3. **轮数上限**：一个用户输入内模型调用次数封顶（具体值见 checklist）；达上限即停、不再调模型，把已产出的文本作为最终答复，并标明「因触发上限而停」。

对外事件流（双路径，不合并为单一 union）：

4. **单向推送流**承载 thinking / text / done 不变，**新增四个循环级信号**让上层感知循环边界：轮开始（带轮次编号）、轮结束（带 stop_reason，区分模型主动结束与仍要继续）、循环结束（带退出原因：自然完成 / 触发上限 / 被取消）、循环错误（带错误类型，与单个工具失败区分开）。
5. **双向决策点保持回调形态**：工具调用 / 结果（on_tool）、执行前确认（confirm）、重试提示（on_retry）不变。理由：单向推送的消费者只管拼接显示、无需回应；确认是需上层回传决定的有状态交互点，不降级成「发事件等配对」的协议。TUI 仅新增循环级信号的渲染分支，文本渲染与确认路径不动。

工具分类执行：

6. **同一轮响应里先并发跑完全部读类工具，再串行跑写类工具**：并发读取缩短「连读多文件」的等待；串行写入保证写操作因果一致。读类 = 免确认（只读），写类 = 需确认（有副作用）。
7. **并发执行、回灌有序、事件实时**：读类并发执行；**tool_result 一律按模型给出的原调用顺序回灌历史**（确定性、可重放、可测）；**on_tool 事件按完成先后 emit**（哪个先跑完哪个先反馈，给上层实时进度），不要求与调用序一致。两者顺序语义有意分开：历史要稳定、UI 要实时。写类逐个确认 → 执行。

plan-only 模式：

8. **`/plan` 切换 plan-only 开关**，底栏显示当前模式（普通 / plan-only）。
9. plan-only 下**读类工具照常执行**（收集上下文）；**写类工具在执行拦截点被捕获、不实际执行**，记为一条计划项（工具名 + 关键参数），并回灌一条「已记录、未执行」的结构化结果，让模型据此继续规划后续步骤、循环照常推进。
10. 循环结束后把**计划列表作为结构化输出**交还用户审批；用户确认**仅退出 plan-only 模式、不自动执行**——人保留最终决策权，下一条用户输入才真正执行写类操作。

取消与超时：

11. **取消经显式取消令牌传入**（而非裸 KeyboardInterrupt 冒泡），循环在**每轮开始与每个工具执行前**检查。
12. **取消后优雅收尾**：对已发起但尚未配对的 tool_use 一律补齐 tool_result（标记为已取消），保证历史中 tool_use 与 tool_result 配对、可重放；已完成的工具结果保留、不回滚不清空；emit 循环结束（原因 = 取消）。仅当本回合尚未产出任何工具 / assistant 块（末条仍是纯文本 user 提问）时，**不把该提问追加进历史**（视作未提交，非历史回滚——append-only 下从不删既有消息）。

## 非功能要求

- **纯对话与单轮自然结束路径产出与 #0001 / #0002 / #0003 完全一致**：不传工具时循环恰一轮即止、首字节延迟不变；循环级信号在单轮场景对用户不可见（轮标记只在第二轮起显示）。
- 工具失败仍转结构化结果回灌模型（#0003 行为不变），循环**不因单个工具失败而中断**——失败是一种结果，模型据此调整后继续。
- 取消后**历史不留悬挂 tool_use**：保存的历史再次 load 不报错、可继续对话。
- 测试不依赖真实网络 / API key（沿用 ScriptedProvider 假事件流 + 临时目录验证）。

## 设计骨架

```
coreagent/
├── agent.py              run_agent_turn 原地改造为多轮 while-loop：
│                         每轮 调模型 → 分类执行(读类并发/写类串行) → 回灌 → 检查四终止条件；
│                         plan-only 拦截写类记计划项；取消令牌在每轮+每工具前检查并优雅补齐；
│                         emit 轮开始/轮结束/循环结束/循环错误 四个循环级信号
├── providers/
│   ├── base.py           事件枚举新增四个循环级信号；推送事件承载轮次/stop_reason/退出原因/错误类型
│   └── anthropic.py      完成事件透出 stop_reason（取自流式最终消息）
├── tui.py                /plan 命令 + 模式底栏；循环级信号渲染分支；
│                         Ctrl+C → set 取消令牌（边界优雅收尾，不再裸冒泡）；
│                         计划列表展示 + 确认后退出 plan-only
└── tests/
    ├── test_agent.py     多轮连环 / 终止 / 上限 / 并发有序 / 取消配平 / plan 拦截 离线用例
    └── test_providers.py stop_reason 透出
```

依赖与结构决策：

- **不引规划器 / 状态图 / LangGraph**：循环就是 while + 终止判断，保持「最小脚手架」。技术栈里的 LangGraph 是远期背景，本 spec 不落地。
- **读 / 写分类复用现有「需确认」标记**：现六工具的「只读 ↔ 免确认」「有副作用 ↔ 需确认」完全对齐，本期不另立只读属性抽象（最简方案优先）。若未来出现「需确认但只读」或「免确认但有副作用」的工具再解耦。
- **取消用显式令牌而非裸 KeyboardInterrupt**：令牌可在循环边界被检查，从而优雅补齐 tool_result、保留可审计轨迹；裸异常难以做到「边界检查 + 配平历史」，并发读时中断点也不可控。
- **事件双路径不合并为 union**：单向推送（渲染只拼接）与双向决策（确认需回传 / 拒绝）消费语义不同；合并会把「事件配对、等待、超时」的复杂度转嫁给上层。把复杂度留在基础设施里、让上层尽量简单。

## Out of Scope

- OpenAI 协议的工具调用 / 循环（沿用 #0003：OpenAI 仍纯对话；`/plan` 对其无写类可拦截，无实际效果）。
- 权限分级 / 目录沙箱 / 命令白名单：deny-first 仅保留 before / after 工具钩子位，具体规则留权限系统 spec。
- 上下文压缩 / compaction：接近上限只记告警事件，不实现压缩管线。
- 子 agent 委派调用。
- 取消后的会话级恢复 / 重放：取消只保留可审计轨迹（配平历史），是否恢复由后续持久层 spec 决定。
- 计划项的模型自然语言改写：直接记「工具名 + 关键参数」并格式化为一行，不额外调一次模型生成描述。
- 工具调用参数逐字流式渲染（沿用 #0003，仅紧凑展示工具名 / 结果）。
